EF2-16a — ESCALADA DE PRIVILEGIOS: auto-promoción a admin
  FLOW:            AUTH/PERFILES (§26)
  PRECONDITION:    usuario autenticado cualquiera (manager o clerk)
  REQUEST:         PATCH {SUPABASE}/rest/v1/profiles?id=eq.<self> {"role":"admin"} con JWT propio
  EXPECTED:        denegado (rol/plan son server-owned)
  ACTUAL:          HTTP 200, fila actualizada → profiles.role='admin' → is_admin()=true → acceso global
  DB DELTA:        profiles.role cambiada (revertida por el harness tras la prueba)
  AUDIT DELTA:     audit_logs CHANGE_ROLE old_data.role→new_data.role (detectable, no bloqueante)
  SECURITY IMPACT: P0 total — cualquier usuario puede obtener admin GLOBAL (todas las tiendas,
                   fiscal lock, stores, bulk ops). Aislamiento multitienda comprometido por cadena.
  ACCOUNTING:      no directo; habilita manipulación con rol elevado.
  ROOT CAUSE:      política profiles_tenant_update: CASE WHEN current_setting('app.use_tenant_rls',true)='true'
                   THEN ((id=auth.uid()) OR (is_admin() AND tenant…)) ELSE (id=auth.uid()) END — en AMBAS
                   ramas el self-update NO excluye columnas sensibles (role, roles, plan, is_active,
                   max_stores_limit). USE_TENANT_RLS no está activado en .env (rama ELSE), y aún activado
                   el THEN permite self-update sin restricción de columnas.
  REPRODUCIBILITY: 100% (reproducido 2×: ALPHA_MANAGER y ALPHA_CLERK; roles restaurados tras prueba;
                   raws/e2e16_rls_security.json)
  CLASS: NEW, CONFIRMED

EF2-16c — PERIODO FISCAL LOCKED REABIERTO POR MANAGER
  FLOW:            FISCAL (§23) — integridad del cierre fiscal
  PRECONDITION:    manager con membership activa; periodo con status='locked'
  REQUEST:         PATCH {SUPABASE}/rest/v1/fiscal_closings?id=eq.<row> {"status":"open"}
  EXPECTED:        bloqueado (prevent_fiscal_closing_edit) y denegado por RLS
  ACTUAL:          HTTP 200 rows=1 → status pasa de 'locked' a 'open'
  DB DELTA:        fiscal_closings.status mutado (restaurado a 'locked' por el harness tras la prueba)
  AUDIT DELTA:     audit_fiscal_closings_changes registra old/new (detectable, no bloqueante)
  SECURITY IMPACT: garantía de inmutabilidad fiscal rota para no-admins.
  ACCOUNTING IMPACT: P0 — un periodo cerrado/bloqueado (cifras fiscales finales) es mutable
                   por un manager; contabilidad posterior al cierre queda desprotegida.
  ROOT CAUSE:      (1) prevent_fiscal_closing_edit: IF OLD.status='locked' AND
                   current_setting('app.bypass_fiscal_lock',true) <> 'true' → GUC sin setear
                   devuelve NULL ⇒ NULL<>'true' ⇒ NULL ⇒ el IF nunca hace RAISE (lock NO-OP).
                   (2) RLS fiscal_closings UPDATE permite por membership.
  REPRODUCIBILITY: 100% (reproducido; restaurado; raws/e2e16_rls_security.json)
  CLASS: NEW, CONFIRMED
