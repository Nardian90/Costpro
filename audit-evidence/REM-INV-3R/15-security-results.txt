== FINDING SEC-F02-1 (P1-leaning hardening, F-02 surface) ==
RLS policies + grants permit an AUTHENTICATED store member to INSERT raw rows into
devolutions + devolution_items (and UPDATE devolutions rows of own store via
devolutions_update_own_store) directly through PostgREST, BYPASSING the create_devolution_v2
contract (no original_transaction_id requirement, no cumulative cap, no stock movement,
no financial counter-entry, no idempotency). This is exactly the ghost-NC shape of F-02,
reachable at the SQL layer by an insider. Mitigating factors: own-store scope only
(no cross-store), requires authenticated membership, app UI never uses this path,
no evidence of abuse in production (all 13 historical NCs predate the policies era and
trace to the API path with audit rows; live INSERT audit exists for v2 docs).

devolutions + devolution_items from anon/authenticated (keep SELECT), forcing all writes
through the service_role-only v2 path; audit the update policy for role restriction.
