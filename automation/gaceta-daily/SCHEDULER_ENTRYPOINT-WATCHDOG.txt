Contable. Un agente nuevo, sin acceso a conversaciones anteriores, debe poder
ejecutar su guardia leyendo solo este archivo. El schedule es SOLO el
disparador: su campo de contenido contiene únicamente la referencia a este
archivo (ver APÉNDICE). NO improvises instrucciones alternativas.

CONTEXTO (2 líneas): El Diario Contable (/gaceta de ADNegocio) se publica a
diario por el schedule-publicador (nivel 1). ESTE watchdog es el nivel 2 de la
cadena: comprueba que la edición del día exista y, si falta, la publica él
mismo. El nivel 3 (auditor del watchdog) vigila que este archivo exista y que
el nivel 2 haya cumplido; no lo sustituye salvo doble fallo.

JERARQUÍA DE FUENTES (patrón CP-CI, sin dos verdades):
  1. docs/OPERATIONS/ADN-GACETA-WATCHDOG-001/PROGRAMA-WATCHDOG.md — normativo.

  3. scripts/gaceta/verify-gaceta-daily.mjs — instrumento de medición.
  Si detectas contradicción: gana el PROGRAMA-WATCHDOG.md; registra el

REGLA MAESTRA: UNA guardia por ejecución, de duración acotada. Al cerrar
(publicada, reparada o bloqueada), escribe el informe y DETENTE.

--------------------------------------------------------------------------------
PASO 1 — MEDIR (read-only, re-ejecutable)
--------------------------------------------------------------------------------
   set -a; source .env; set +a
   node scripts/gaceta/verify-gaceta-daily.mjs --verbose
Criterios (salida literal del script):
- exit 0 + "RESULTADO: OK" → la edición del día existe → guardia SATISFECHA:
  escribe informe (sección INFORME) con la salida literal y DETENTE. No toques
  la base.
- exit 2 + "RESULTADO: HUECO" → continúa en PASO 2.
- exit 3 → error de entorno/conectividad: 3 reintentos con pausa de 60 s;
  si persiste, informe BLOCKED y DETENTE.

--------------------------------------------------------------------------------
PASO 2 — REPARAR EL HUECO DE HOY (publicar la edición del día)
--------------------------------------------------------------------------------
1. Decide el tipo de la edición del día:
   a. Novedades oficiales verificables del día (Gaceta Oficial de Cuba,
      ONAT, MIPymes) → nota tipo 'gaceta' (voz periodística, con fuente).
   b. Sin novedades verificables → nota tipo 'costpro' (novedad real de
      ADNegocio basada en el repo: changelog, audits, features recientes).
   PROHIBIDO mezclar hechos oficiales inventados con notas de plataforma.
2. Redacta en el formato del contrato ADN-011:
   - titular (<= 120 chars), bajada (1 frase), cuerpo = array de bloques
     { "t": "h2"|"p"|"li"|"quote"|"dato", "v": "<texto>" },
   - etiquetas: máximo 4, minúsculas, sin espacios (guiones si hace falta),
   - fuente: URL real citada (tipo 'gaceta') o null (tipo 'costpro'),
   - slug: gaceta|costpro-<fecha>-<slug-corto>, único.
3. INSERT idempotente (service_role, la ÚNICA escritura permitida):
   POST {SUPABASE_URL}/rest/v1/gaceta_posts
   Headers: apikey + Authorization Bearer SERVICE_ROLE, Content-Type
   application/json, Prefer: return=minimal
   Body: {"fecha": "<hoy-La-Habana>", "slug": ..., "tipo": ..., "titular": ...,
          "bajada": ..., "cuerpo": [...], "etiquetas": [...],
          "fuente": ..., "destacado": false, "estado": "publicada"}
   Slug repetido (reparación ya hecha) → HTTP 409: aceptado como ya-publicada;
   NO reintentar con otro slug.
4. Verificación POST (re-ejecutar PASO 1): exit 0 y "RESULTADO: OK" con la
   nota del día visible en public_gaceta_v → guardia REPARADA.
5. Huecos históricos ANTERIORES a hoy (días sin edición): NO se rellenan
   automáticamente (decision editorial del propietario). Se listan en el
   informe como "huecos pendientes de decisión" con las fechas exactas.

--------------------------------------------------------------------------------

Sin secretos ni tokens. Este archivo es el registro que lee el nivel 3.

TERMINACIÓN: tras el informe, DETENTE. No publiques ediciones extra, no
